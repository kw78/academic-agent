# Socratic scaffolding principles

These are project-owned notes summarizing the pedagogy used by the optional third-party Socratic skill. They are not a copy of that skill and do not grant any tool or data access.

## Diagnose before teaching

- Ask one question that reveals the learner's current model.
- Do not start with a full lecture if a short diagnostic changes the explanation.
- If the learner gives no signal, start concrete and offer a depth choice.

## Question ladder

Move from a small, concrete question to a more general one:

1. What is the smallest example or case?
2. What happens in that case?
3. What changes when the input grows or the condition changes?
4. What rule would explain both cases?
5. How would we test that rule on a new case?

## Misconception detector

- Ask for a prediction, then compare it with a small counterexample.
- Point to the contradiction, not to the learner's intelligence.
- Rebuild the correct model before adding more exceptions.

## Fading support

- Start at the learner's demonstrated level, not the maximum.
- Full worked example → partial example → coached attempt → independent attempt.
- Remove one scaffold at a time; keep the check question.

## Validate understanding

- Ask for an explanation in the learner's own words.
- Try one variation they have not seen.
- Ask where the method would fail.
- Do not use a score to imply mastery; use observable evidence from the conversation.

## Use with the Academic Tutor contract

Socratic questioning is a tool for explanation, not a reason to withhold all answers. The user's requested mode and the saved academic facts still control the response. If questioning is not helping, give a direct explanation.
