## 1. 目的与范围

在现有 Event-Sourced Academic Kernel 与 DSH/Cordis
之上，提供日常可用的学业管理界面，不另造应用框架。

原则： - 长期理念是可个性化、可扩展的个人助手；当前范围是单用户学业管理
MVP。 - DSH 提供 Agent、插件宿主和客户端容器；Academic Agent
提供学业业务能力。 - DSH Desktop 与 DSH Web 复用同一套 Academic
UI，不维护两套业务界面。 - UI
是可替换的交互层，不是领域内核或业务事实来源。 -
普通操作通过确定性查询、命令和规则完成；只有真正需要推理时才进入
Agent。 - 不因增加前端而重写 Kernel、Event Store、Scheduler、Planner 或
Credential Vault。

本轮不做：独立 Electron/Tauri 桌面壳、脱离 DSH 的独立 Web 产品、多用户
SaaS、跨设备同步、插件市场、复杂日历拖拽、重写 DSH Chat/Session/审批
UI。

## 2. 关键架构决策

### FE-DEC-01：复用 DSH Desktop 与 Web

DSH Desktop 是 Electron 外壳，承载 DSH Web 客户端；两者不应分别实现业务
UI。采用一套 DSH Client UI
插件，优先使用锁定版本支持的客户端插件、导航和 UI Slot 扩展机制。

React 组件不得直接调用 Electron API、Node 文件系统或原生
IPC。桌面特有能力只能经由 DSH Host 提供的受控接口访问。

### FE-DEC-02：UI 与 Host 分离

Host 负责权威状态、持久化、权限、业务命令和后台任务；Client
负责呈现、输入和交互反馈。UI 不直接访问 SQLite、Event Store、核心
Projection、Scheduler 表或 Credential Vault。所有读取经 Query
API，所有业务变更经 Command API。

### FE-DEC-03：UI 与后台能力独立生命周期

-   卸载 UI 不得停止同步、提醒、Planner 或后台任务。
-   关闭聊天 Session 不得影响 Academic 状态。
-   卸载 Agent Bridge 不得影响 UI 的普通查询和后台自动化。
-   Host 停止时，UI 显示服务不可用并允许重试；不得在客户端创建第二份
    Academic Runtime。

### FE-DEC-04：同一数据库只允许一个权威 Host 写入者

Desktop 与独立 Web Profile 可能使用不同
Profile、数据目录和运行时，不能假设天然共享数据库。若使用不同
Profile，应明确视为不同数据实例；若要共享，必须明确配置同一受支持的
Host/Profile，并验证并发访问与生命周期。

不得为了 UI 再执行 CLI 组合根，创建第二份 Scheduler、Dispatcher 或
Connector Runtime。检测到数据库已被其他 Host
占用时，应明确报错或只读退出。

### FE-DEC-05：先验证锁定版本

当前项目验证版本为 DSH 0.2.1-rc.3。当前主分支的 UI Slot、Client Module
或 Remote API 不能自动视为锁定版本已提供。UI-0
必须验证实际版本的插件加载、导航扩展、Host/Client
通信和构建流程。若必须升级，记录 ADR 并重跑兼容测试；不得默认 fork DSH
或另建插件 Loader。

## 3. 总体架构

``` mermaid
flowchart TB
    Desktop["DSH Desktop / Electron"] --> UI["Academic UI Plugin"]
    Web["DSH Web / Browser"] --> UI
    UI --> API["Academic Host API Adapter"]
    Chat["DSH 原生 Agent Chat"] --> Tools["Academic Agent Tools"]
    API --> Query["Academic Query API"]
    API --> Command["Academic Command API"]
    API --> Connections["Connection Manager"]
    Tools --> Query
    Tools --> Command
    Command --> Kernel["Academic Kernel"]
    Kernel --> Store[("SQLite Event Store")]
    Kernel --> Projection[("Core Projections")]
    Query --> Projection
    Runtime["Scheduler / Connector / Planner / Notifications"] --> Command
    Runtime --> Query
    Connections --> Vault["Credential Vault"]
```

Desktop/Web 是 UI 入口，不代表两个独立 Host 可以同时写同一数据库。

### 查询流程

UI 通过 DSH 当前版本支持的 Host/Client 通信调用 Query API；Query API
从核心 Projection 读取；Client 展示来源、更新时间和同步健康信息。

### 变更流程

用户操作 → Command API → Host 校验参数、权限、版本和业务不变量 → Kernel
事务写入事件与核心 Projection → 返回成功或结构化失败 → UI 刷新相关查询。

UI 可以显示 Pending，但不得先伪造持久化成功。最终状态以 Host 结果为准。

### 与 DSH Chat 的关系

继续复用 DSH 原生聊天承担自然语言问答、课程解释、复杂问题和按需 Agent
工作。Academic UI
承担结构化状态、列表筛选、计划管理、连接和自动化控制。不重复实现聊天、模型选择、Session
或工具审批 UI。从作业跳转聊天时只传非敏感业务 ID 和问题，不传凭据。

## 5. 页面与 MVP 功能

### 5.1 总览 Dashboard

显示今日待办、近期截止事项、今日学习计划、近期作业/考试变化、未读提醒、数据源状态、最近成功同步时间、认证失效和未安排任务。

只显示 Query API 的事实。未知截止日期不得伪装成确定日期；Agent
建议不得显示为已确认计划。同步失败时保留最后有效数据并显示其时间。

### 5.2 作业与任务 Tasks

支持按课程、事项类型、截止范围和状态筛选；查看标题、课程、来源、截止时间、源更新时间、本地任务状态和来源链接；标记完成/重开、调整预计时长、查看未安排原因。

学校原始作业事实与用户学习任务分开展示。本地任务完成不等于学校已提交。同步不得覆盖用户修改的耗时、备注或完成状态。所有变更调用
Command API。

### 5.3 学习计划 Plan

首版提供日视图、周视图和列表，不要求复杂拖拽日历。支持查看已确认/候选计划、计划块、固定课程和锁定时段；预览重规划、确认/放弃候选计划、锁定/解锁时间段、查看未安排原因、修改可用时间。

规划算法确定性执行，不调用
LLM。候选计划与确认计划是不同状态；不得静默覆盖已确认计划，除非用户明确启用自动确认策略。锁定时段是硬约束。无法安排时解释原因。Planner
卸载后已有计划仍可查询。

### 5.4 课程与数据源连接

显示课程名称、学期、关联来源；数据源名称、Adapter
是否可用、连接状态、脱敏账号标识、授权范围、上次验证/同步时间、最近失败原因、自动同步开关和周期。

状态至少区分：未配置、已配置未验证、已连接、需要重新认证、同步降级/失败、已断开、当前版本不支持。

不能仅因凭据已保存就显示平台可正常同步。只有真实验证或成功同步后才能显示已连接/最近成功。Adapter
未实现时标记暂不可用，不得暗示能接入任意网站。

### 5.5 自动化与通知

显示同步启停状态、下次执行时间、最近运行记录、成功时间、连续失败次数、错误说明、提醒开关/阈值和未读提醒。用户可暂停/恢复支持的自动化；暂停后既有学业数据仍可查询。MVP
不提供任意 Cron 编辑器或任意脚本执行界面。

### 5.6 设置

包括时区、每周可用学习时段、临时不可用时间、计划粒度、提醒开关/阈值、同步周期和基础
UI 偏好。业务偏好通过 Host API 持久化；筛选器、排序和展开状态等纯 UI
偏好可本地保存。不得将密码、Token、Cookie 或凭据引用存入浏览器存储。

### 5.7 Agent 辅助

复用 DSH Chat。可提供"解释这个作业""帮我拆解任务"等入口，传递非敏感业务
ID 和问题。Agent
建议必须与数据库事实区分；涉及计划变更时先预览/确认。点击入口不代表授予
Agent 写权限。

## 6. Host API 约束

本文定义逻辑能力，不冻结 DSH Remote 方法名；真实签名在验证 0.2.1-rc.3
后确定。

### 查询能力

Dashboard
Summary、课程列表/详情、事项列表/详情、任务列表/状态、当前计划/候选计划/锁定时段、可用时间、连接元数据/状态、同步历史/自动化状态、通知列表/未读数。

查询必须分页或限制返回量。响应包含必要来源、更新时间和状态信息，不返回秘密。

### 命令能力

任务完成/重开/改预计时长、设置可用时间、生成候选计划、确认/放弃计划、锁定/解锁时段、手动同步、暂停/恢复自动化、修改提醒、通知已读、创建/验证/重新认证/断开连接、删除凭据。

所有写入经现有 Command API。Actor 与权限由 Host 确定，不信任 Client
自报身份。校验失败、并发冲突、能力缺失、认证失效使用不同错误码。不提供通用任意字段更新接口，不允许
UI 直接发领域事件。重复提交依靠幂等键或等价机制。

### 状态刷新

优先使用锁定版本实际支持的 Remote 查询/订阅能力。若没有可靠状态流，MVP
可在页面激活时查询、操作成功后刷新、提供手动刷新；必要时对运行状态使用有上限的轻量轮询。不得为
UI 单独引入 WebSocket 或消息队列。

## 7. 凭据与连接安全

-   仅对已实现且明确支持的 Adapter 展示认证表单。
-   密码输入使用 password 类型，不回填已保存秘密。
-   密码/Token 只在当前交互内存中短暂存在，提交后清空字段。
-   不写入
    localStorage、sessionStorage、IndexedDB、URL、浏览器历史、分析事件或错误报告。
-   不放进 Agent Prompt、工具输出、Domain Event、普通日志或同步记录。
-   通过 DSH 锁定版本支持且经过认证的 Host 通信入口提交。
-   Host 对认证请求、异常和追踪信息脱敏，不记录原始请求体。
-   UI 不访问 Vault，不接收 `credential_ref`；只获得连接
    ID、状态、脱敏账号标识和可展示的授权范围。
-   Vault 只由受信任 Host 连接服务访问；Agent Tools 不依赖 Connection
    Manager/Vault。
-   Adapter 仅能在指定 source/connection 授权下取得短期凭据租约。
-   断开/删除凭据不删除已同步学业数据；Vault
    不可用时失败关闭，禁止明文回退。

MVP 是单用户本地应用，凭据归属运行 Academic Host
的操作系统用户。远程浏览器、多用户和共享 Host
的多账号凭据不属于默认范围。未来开放远程访问前，必须设计用户身份、会话绑定、传输保护、权限隔离和每用户
Vault 所有权。

## 8. Desktop/Web 运行模型

Desktop 与 Web 复用 UI 代码，但数据是否相同取决于 Profile、Host
和数据库配置。界面可显示 Profile 标识、Host
是否可用、连接是否有效；不要暴露不必要的绝对本地路径。

Host 由 DSH Host 插件生命周期管理。UI 加载、卸载或 HMR 不得创建/关闭
Host。Host 只初始化一次 Event Store、Dispatcher、Scheduler 和 Connector
Runtime。退出时停止新任务、处理在途任务并释放订阅、定时器和文件句柄。

Host 断开时显示服务不可用；恢复后重新查询。不得在浏览器端启动 CLI
子进程来补齐 API。

文件选择、打开本地资料和系统通知只能通过 DSH 已提供且经过授权的 Host
能力实现。首版不得直接暴露 Electron IPC
或任意文件系统权限。锁定版本不支持的能力暂缓或使用受限替代方案。

## 9. 页面状态、交互和可访问性

每个主要页面支持：

-   Loading：首次加载；
-   Empty：没有课程、事项、计划或连接；
-   Ready：数据可用；
-   Stale：有最后有效数据，但最近同步失败或数据可能过期；
-   Degraded：部分来源/能力不可用；
-   Auth Required：需要重新认证；
-   Conflict：命令版本冲突或状态已变化；
-   Unavailable：Host 或可选插件不可用；
-   Error：请求失败并提供重试入口。

必须区分学校事实、用户本地状态、Planner 候选建议、已确认计划和 Agent
建议。未知、缺失、过期或部分抓取数据不得显示为确定事实。查询失败不得伪装成没有作业。错误提示给出可执行的下一步；原始堆栈仅写入脱敏日志。

交互原则：先呈现任务和行动；复用 DSH
主题与组件；破坏性操作明确确认；状态不能只靠颜色表达。桌面宽屏可双栏，窄窗口改单栏，移动浏览器保证任务查询、完成状态和提醒可用，复杂计划可降级为列表。主要操作可键盘完成；表单有标签和错误提示；模态窗口正确管理焦点。

本地只保存非敏感 UI 偏好。课程、任务、计划和可用时间必须由 Host
持久化状态恢复。

## 10. 可观测性

UI
至少展示最近成功同步时间、最近失败原因、认证状态、待处理/未安排任务数、计划确认状态、最近提醒和
Host/插件不可用状态。

诊断可记录 request ID、correlation
ID、错误码、耗时和版本；禁止记录密码、Token、Cookie、Authorization
Header 或完整敏感响应体。必须区分查询失败和数据为空。

## 11. 测试规范

### 单元测试

覆盖页面状态映射、筛选排序、错误码提示、候选/确认计划区别、未知截止时间和过期数据、凭据提交后清空，以及不将秘密写入客户端持久存储。

### Host API 集成测试

覆盖 Query API 只读现有 Projection、UI 命令进入 Command
API、失败不假报成功、并发冲突提示、连接状态不泄露秘密、缺失能力明确报错、Host
断开后可恢复查询。

### DSH 宿主测试

必须在锁定 DSH 0.2.1-rc.3 上验证： - UI
插件加载、学业入口注册、页面挂载； - Host/Client API 通信； -
卸载后入口和订阅清理，重载后无重复； - Desktop 与 Web Profile 正常； -
UI 卸载不停止后台同步和提醒； - Host 停止后 UI 显示不可用； - UI
重载不会创建第二个 Scheduler/Dispatcher。

若锁定版本缺少扩展点，应记录缺口，不能用 Mock 冒充宿主验收。

### 端到端测试

使用 Fixture LMS 验证：打开 UI → 读取课程/作业 → 手动同步 →
新作业进入任务列表 → 预览计划 → 确认计划 → 修改任务状态 →
刷新/重启后状态保留 → 同步失败时保留旧数据并标记 Stale →
凭据失效时提示重新认证 → 卸载 UI 后后台任务继续。

Fixture E2E 不等于真实 LMS 验收。

## 12. 分阶段实施

### UI-0：宿主验证与最小入口

检查 DSH 0.2.1-rc.3 的 Client Plugin、UI Slot、导航、Host/Client API 和
Bundle 构建；建立最小学业入口，通过真实 Query API 显示课程列表；验证
Desktop/Web、卸载和 Host 生命周期。交付可运行原型、验证记录和必要 ADR。

### UI-1：只读总览

实现 Dashboard、课程列表、作业/考试列表与详情、来源/截止/同步状态，以及
Loading/Empty/Error/Stale 状态。所有数据来自 Query API。

### UI-2：任务与计划交互

实现任务完成/重开/预计时长修改、可用时间设置、候选计划预览/确认/放弃、锁定/解锁和未安排原因。所有变更经
Command API。

### UI-3：数据源连接与凭据安全

实现连接状态、受支持来源的认证表单、重新认证、断开/删除凭据和同步错误信息。验证秘密不进入浏览器存储、事件、普通日志或
Agent 上下文。

### UI-4：自动化、提醒与体验完善

实现自动化启停、同步记录、通知已读、提醒设置、响应式和可访问性。UI
只展示后台状态，不复制后台执行逻辑。

## 13. 完成定义

-   [ ] Academic UI 作为 DSH Client 扩展加载，不是重新构建的 Harness。
-   [ ] 同一 UI 在已验证的 DSH Desktop 和 Web 环境运行。
-   [ ] 锁定版本的插件接口和构建方式有真实验证记录。
-   [ ] UI 不直接访问 SQLite、Event Store 或 Credential Vault。
-   [ ] 所有业务变更经受控 Command API。
-   [ ] 总览、任务、计划、连接和自动化状态有可用页面。
-   [ ] "已保存凭据"不会误报为"平台已验证可用"。
-   [ ] UI 卸载不影响 Host、Scheduler、Dispatcher 和后台同步。
-   [ ] UI 挂载/重载不会重复创建 Host。
-   [ ] 凭据不写入客户端持久存储、事件或普通日志。
-   [ ] Loading、Empty、Stale、Auth Required、Conflict、Unavailable
    状态正确。
-   [ ] 核心 E2E、Host API 和锁定 DSH 版本测试通过。
-   [ ] 文档明确列出未验证能力，不把计划写成已实现。

## 14. 明确禁止

-   不创建第二套 Electron/Tauri 桌面壳作为首版。
-   不为 Desktop 和 Web 复制两套业务 UI。
-   不启动第二份 Academic Runtime 服务 UI。
-   不让 UI 直接操作 Event Store、Projection、Scheduler 表或 Vault。
-   不在 Client 中复制领域规则或 Planner 算法。
-   不把 Agent Chat 当作唯一学业管理界面。
-   不将普通查询、同步、去重、提醒或基础规划改成 LLM 工作流。
-   不在前端存储密码、Token、Cookie 或凭据引用。
-   不让模型参数自证用户授权。
-   不因 DSH 主分支 API 存在，就假设锁定版本已支持。
-   不为首版引入身份平台、多租户、微服务、插件市场或任意脚本执行界面。

## 16. 日常使用导向的 UI 改进设计（2026-10-28，已实施；部分边界待验收）

### 16.1 分析结论与证据边界

依据 Intent §4–5、Architecture Spec §6/13–16、Roadmap、两份验收记录，以及当前
`packages/academic-dsh-ui/src/client` 页面、`api.ts`、`protocol.ts` 的静态审查。
本轮没有启动 Desktop/Web、访问真实平台或开展用户测试；以下是由代码与文档推导的设计判断，不能当成实测可用性结论。

| 现状与证据 | 用户影响（设计判断） | 改进决策 |
|---|---|---|
| `index.tsx` 七个平级页签；课程管理在 `ConnectionsPage.tsx`，课程优先级在设置页 | 查看一门课的任务和资料需要跨页重新选课 | 日常与管理导航分组；增加课程工作区，共享课程上下文 |
| `DashboardPage.tsx` 先展示四个统计卡；今日待办位于计划/截止区之后，待办行没有完成入口 | 用户先读统计再寻找下一项行动 | 总览改称“今天”，首屏展示下一学习时段、今日任务和需要处理的异常 |
| `ConnectionsPage.tsx` 已将添加平台置顶，也已有 `stage/nextStep`；卡片仍并列登录、录制、探测、预览、同步和危险操作 | 已有下一步提示，但按钮层级尚未收敛 | 保留链接配置置顶；每个来源一个主动作，技术详情与危险操作按需展开 |
| `TasksPage.tsx` 已有学习任务/来源事项/复习清单切换，单行还承载多种管理操作 | 来源事实与本地工作存在关联，但需要用户自行对照 | 保留三种视图，任务为默认；详情集中展示关联来源和本地覆盖 |
| `PlanPage.tsx` 有候选统计、未安排原因、锁定及日/周/列表；有活动计划时确认候选被禁用，需先归档 | 用户难判断候选带来什么变化及下一步 | 增加候选与当前计划对照，明确归档再确认流程及中间失败恢复 |
| `api.ts` 在 `loadTasks` 截断任务，在 `dashboard` 截断近期事项为 20 条后计数；`DashboardView` 无截断说明 | 统计可能只是已加载数量，筛选可能漏掉范围外记录 | 全量聚合计数与分页列表分开，过渡期明确标注范围与截断 |
| `MaterialsPage.tsx` 已有检索/导入双栏、关键词高亮和页码；验收记录已有浏览器点验 | 该结构可复用，但跨页课程定位仍需改善 | 保留资料页布局，统一课程上下文与引用入口，不重新设计已验证的导入链路 |

核心决策：先让用户看清“今天做什么、哪些事实变了、遇到问题下一步做什么”；不增加模型调用、独立桌面壳或新的领域聚合。

### 16.2 信息架构与上下文

继续使用 DSH 的单个“学业”入口。面板内导航分成两组，使用宿主样式，避免再造一层应用外壳。

| 分组 | 页面 | 主要职责 |
|---|---|---|
| 日常学习 | 今天（原总览）、任务、计划、课程、资料 | 查看与完成学习工作；课程页复用现有查询和命令 |
| 管理 | 连接、自动化、设置 | 平台接入与修复、后台运行、全局偏好 |

“课程”提供学期筛选、课程列表和课程详情；详情汇总待办、来源事项、已确认安排、资料入口和关联来源健康。
课程编辑/归档/删除/恢复从连接页迁入课程页；课程合并仍置于设置的维护区，并沿用先备份再合并的 Host 流程。
课程优先级可在课程详情调用现有偏好接口修改；设置保留全局汇总，二者读取同一份 Host 偏好。
不新增复杂课表编辑器；没有真实固定课程数据时不画出虚构课表。

导航在客户端传递有类型的页面、`courseId/taskId/itemId/sourceId` 和筛选条件，并保留返回位置；这是 UI 上下文，不授予写权限。
从“今天”进入逾期任务、从课程进入资料、从异常进入指定来源时，直接定位对象并带筛选；返回后恢复筛选与滚动位置。
跨页默认沿用选中课程，同时提供醒目的“全部课程/清除筛选”；首次无明确课程上下文时不得静默选第一门课程作为导入目标。
删除或归档后的对象显示状态及返回入口，不悄悄替换成另一对象。浏览器仅可保存非敏感导航偏好；业务状态仍由 Host 恢复。

### 16.3 “今天”的内容与操作

以下为宽面板的内容顺序示意；数字与时间只使用 Host 真实返回值：

```text
学业    今天 / 任务 / 计划 / 课程 / 资料       管理入口
日期 · 业务时区                  新建任务    提醒入口（未读数）
[需要处理：某平台需重新登录；显示最后有效数据] [去处理]
┌ 主栏：下一已确认学习时段 / 今日任务 ┐ ┌ 辅栏：未来 7 天截止 ┐
│ 时间 · 课程 · 标题 · 预计时长      │ │ 课程 · 事项 · 截止   │
│ [完成] [查看详情]                 │ │ [查看全部]          │
└──────────────────────────────────┘ └─────────────────────┘
未安排任务摘要 [查看原因]   近期变化摘要 [查看来源]
最近成功同步时间 · 后台状态 [管理连接]
```

今日任务口径为“业务时区内今日截止或今日存在已确认计划块的未完成任务”，按 taskId 去重；逾期未完成单列提示，不能被今日筛选隐藏。
下一学习时段只从已确认计划产生；没有计划时展示“查看任务/生成计划”，不把候选或 Agent 建议充当实际安排。
每行直接完成/重开，调用现有任务命令；返回成功后刷新相关数据。失败保留原状态，焦点留在原任务。
主栏默认最多展示 5 条，提供带相同口径的“查看全部”；摘要计数来自全范围查询，不能取这 5 条的长度。
统计改为可进入相应筛选的紧凑摘要，未读提醒不再同时占据统计卡和完整列表。全局“咨询 Agent”降为次级入口，课程/任务/资料详情保留带上下文的提问动作。
普通同步留在来源详情；“今天”显示状态和修复入口，避免语义不明的全局同步按钮。

### 16.4 任务列表与详情

默认显示未完成任务；提供今天、未来 7 天、逾期、未安排、全部快捷筛选，并保留课程、类型、状态和搜索。
时间范围按用户业务时区计算；仅日期的截止只显示日期和“仅日期”，未知截止进入独立分组，均不制造精确倒计时。
列表优先展示：完成控件、标题/课程、有效截止、预计时长、安排状态；编辑、删除/恢复与教学入口放进详情或“更多”。
来源事项视图继续独立存在；详情明确关联的学习任务，避免把同一作业和默认任务当成两份待完成工作。

详情宽屏用侧栏，窄屏为页内详情；包括本地任务状态、来源平台提交状态、源截止、本地覆盖后的有效截止及覆盖原因、来源链接和更新时间。
历史只显示已有事件/历史查询能够证明的变化；暂只有 `updatedAt` 时标“最近更新”，不得编造“截止从 X 改为 Y”。
归档/删除说明具体影响；可恢复的软删除成功后提供“恢复”入口，仍调用恢复命令，不直接回滚界面数据。
学校来源字段不作为本地可编辑字段；本地完成始终显示“本地已完成”，不会显示“学校已提交”。

### 16.5 计划：候选、差异与确认

当前已确认计划为默认视图；候选通过显式预览进入，展示区间、业务时区、已安排/未安排分钟、容量、未安排原因及锁定时段。
对照按 taskId 与时间区间标出新增、移时、移除、未变化；只比较 Host 返回的计划块，不在客户端重新规划。
容量不足、截止已过、缺少可用时间等原因沿用 Planner 的结构化结果；每类原因提供具体入口，如修改预计时长或可用时间。
锁定使用图标及文字，在日/周/列表中均可识别；不增加拖拽日历作为本轮前置条件。

第一轮沿用“归档旧计划 → 确认候选”的既有命令约束：预览阶段保留旧计划；归档前说明影响，保留候选并展示两步进度。
归档成功但确认失败时明确显示“旧计划已归档，候选尚未确认”，允许重试或重新生成，不能显示全部完成。
确认仍只提交 Host 保存的 `previewId`；任务/锁/可用时间变化后由 Host 校验有效性，过期或冲突提示重新预览。
本轮不增加原子替换计划命令；若后续确需一键替换，须另行设计领域不变量、事务和失败恢复，再实现 UI。

### 16.6 连接：一个来源、一条接入主线

“添加平台”与链接配置继续固定在连接页最前；支持已有能力时走常规登录验证，未知解析需求再转录制/Agent。
概览每个来源只显示名称/站点、登录源或同步源标识、阶段、最近有效数据时间、一个主动作及“更多”。
登录源与自动创建的同步源可在视觉上关联展示，但保留各自 sourceId、状态和操作范围，不按标题猜测后合并配置。

| 当前条件 | 主要呈现与动作 |
|---|---|
| 尚未登录或认证过期 | “登录平台/重新登录”；说明已有数据保留 |
| 会话已保存但未验证 | “验证连接”，不能显示为同步成功 |
| 已验证但无可用解析能力 | “录制课程/作业页面”；已有足够证据时进入候选流程 |
| 录制无目标列表、样本过期或传输不支持 | 按 Host 给出的原因提示重新录制/补打开目标栏目/当前暂不支持；不反复让模型猜接口 |
| 候选可验证或已验证 | “验证候选/查看验证报告”，随后按授权策略启用；样本回放不等于真实同步 |
| 同步能力就绪但未做真实预览 | “预览同步”，展示新增/更新/未变/跳过与警告，再显式执行首次同步 |
| 正常运行 | 显示下次同步时间；手动同步为次级操作 |
| 同步失败或部分成功 | “查看问题”，区分认证、网络、权限、结构、质量，不统一诱导重新登录 |

表中动作由 Host 的来源阶段、下一步、录制证据与候选报告组合决定；当前 `SourceNextAction` 无法表达的分支按 16.9 补契约，客户端不另造权威状态机。
录制引导用普通语言要求用户依次打开课程列表、作业/考试页，按需翻页后完成；先显示已发现的业务栏目与缺口，再展开接口清单。
原始响应继续只在宿主样本库；界面只展示脱敏清单与有效期。分段录制、DOM 点选等仍属[发现架构评审](../docs/adapter-discovery-architecture-review.md)的建议，不在界面伪装成已支持。
候选审批区默认展示站点/路径范围、数据类型、验证阶段、失败原因、真实同步是否验收；Manifest JSON、摘要、字段路径和运行诊断放高级详情。
权限文案读取默认关闭的“Agent 自动接入”偏好：关闭时逐次授权；开启时明确允许的 validated declarative 启用/预览/同步范围，不能仍声称所有启用均需点击确认，也不能扩大到任务修改或凭据访问。
取消浏览器登录、录制失败或样本失效只结束当前步骤；保留已有来源、有效会话与学业数据，以 Host 结果为准。

### 16.7 资料、自动化与设置的收敛

资料页保留已验证的列表/导入布局；从课程或任务进入时显式显示目标课程，未选课程时要求选择后导入，检索结果保留标题、页码、片段与 Agent 引用上下文。
无文本层资料显示“未提取到文字”；上传、抽取、可检索为不同状态，不虚构抽取百分比或 OCR 能力。附件自动导入继续按 source+course 单独授权。
自动化页聚焦作业启停、下次执行、失败与恢复；提醒从各页统一入口打开，读写共用通知 ID。提醒设置与同步周期复用同一份 Host 配置，不在多个页面维护草稿副本。
设置分为学习时间、提醒与同步、Agent 权限、维护与诊断；可用时间编辑只有一个实现，计划页和引导页复用它。
首次进入提供“添加平台或手动建课 → 查看任务 → 检查可用时间 → 预览并确认计划”的可跳过引导；状态从真实查询推导，不能用浏览器里的“引导完成”标记代替实际配置。

### 16.8 视觉与交互规则

- 复用 DSH 主题和字体，将当前分散的样式收敛为面板内变量：间距 4/8/12/16/24/32 px；正文默认 14 px、辅助文本至少 12 px，圆角 8/12 px。主按钮只用于当前步骤的核心动作。
- 颜色按正常/进行中/待确认/异常表达，并辅以文字和图标；逾期红色只用于真实逾期或失败，不把未知截止渲染为逾期。
- 按学业面板可用宽度适配：≥1040 px 主辅双栏；720–1039 px 单栏或列表加可关闭详情；<720 px 单栏详情和筛选折叠。以 DSH 侧栏挤压后的面板宽度验收，不只看浏览器窗口宽度。
- 交互目标至少 32×32 px，触屏目标至少 44×44 px；正文对比度目标 4.5:1。正常/暗色主题均需实际检查，不仅降低 opacity 表达次要内容。
- Loading 保持原布局；刷新保留旧数据。分别展示查询失败、来源同步失败、部分成功、未接入、筛选无结果与真实空数据，不将错误变成“没有作业”。
- 标明“界面刷新时间”和“来源最近成功同步时间”的不同含义；部分成功注明未覆盖范围，不将其他来源的成功当成该来源已恢复。
- 操作 pending 关联到具体对象；同对象防重复提交，其他独立对象可继续操作。破坏性操作明确对象、影响、恢复方式，再确认；大范围课程删除或来源彻底删除用完整说明，不能只改按钮文字。
- Tab 导航有可见焦点、方向键/Home/End 和面板关联；详情打开/关闭恢复焦点，Esc 关闭临时层，错误与结果可被辅助技术读取。支持减少动画，不能仅悬停显示必要动作。

### 16.9 Host 契约与实现边界

先复用 `DashboardView`、`TaskCard`、`PlanView/PlanCandidate`、`CoursesView`、`SourceStatus`、候选报告和现有领域命令。下列为待实现契约要求，不是已有 API 保证：

1. 摘要提供全范围计数、统计口径/区间、生成时间和完整性标识；列表独立限制长度。过渡期明确“已加载 N 条/仅显示前 N 条”，不能把截断后的长度当总数。
2. 任务/事项筛选、稳定排序与分页由 Host Query 层执行，关联来源字段也须覆盖当前页；不能先截 500 条再让客户端筛选“全部”。课程汇总组合现有查询，不新增课程业务事实表。
3. 详情所需历史、候选差异和上下文导航按需补最小 DTO；历史不足时降级显示已有更新时间。展示差异可由客户端比较权威快照，决定可否确认仍在 Host。
4. 来源/发现下一步须能区分验证、补录制、样本失效、传输不支持、候选验证/授权与同步预览；补运行时 Schema 和 Host 测试后 UI 才依赖新分支，不把样本存活信息存成领域事件。
5. 操作成功后重新查询相关页面，跨页失效只传非敏感对象 ID；不引入新消息队列或第二份 Runtime，不把 React 状态当权威缓存。沿用页面激活、操作刷新与有上限轮询。

新增 DTO/查询在 contracts 与 Host 适配层评审；领域变更仍经 Command Handler，source/偏好/资料等运营数据沿用各自受控应用服务，不强行事件化。导航与颜色调整不需要数据库迁移。

### 16.10 验收与实施映射

执行任务见 [Roadmap §16.1](ACADEMIC_AGENT_ROADMAP_MVP_FIRST.md#161-ui-改进执行队列2026-10-28新增)。2026-10-28 已完成实现并通过自动化与 DSH Web 点验，证据见 [前端验证记录](../docs/frontend-verification.md#日常使用导向-ui-改版2026-10-28)；Desktop、暗色主题、真实登录与计划失败注入仍待专项验收。

| 用例 | 可检查的通过条件 |
|---|---|
| 今天开始学习 | 有数据时首屏可识别下一已确认时段或今日任务；完成操作后详情/汇总刷新，重启仍保留；无计划不显示虚构安排 |
| 跨页定位 | 从课程进入任务/资料携带 courseId；从异常进入对应 sourceId；返回保留筛选，不默认导入第一门课 |
| 数据完整性 | 501 个任务、21 个近期事项样本下，统计仍完整或明确标注不完整；后页记录可被 Host 筛选检索到 |
| 事实边界 | 精确/仅日期/未知截止、源截止与本地覆盖、本地完成与学校提交均可区分；历史不虚构 |
| 接入与恢复 | 链接配置置顶；每阶段一个主动作；未验证/无适配器/样本过期/网络故障分别给出可执行下一步；旧数据仍可见 |
| 授权 | 自动接入关闭/开启均显示实际策略；候选回放与真实同步分开标注；点击 Agent 入口不授权任务写入 |
| 计划 | 候选与当前计划可对照，锁定可识别；旧计划归档后确认失败有真实中间态，过期 previewId 不能确认 |
| 视觉与键盘 | 1280/1000/720/390 px 面板、明暗主题、长中文标题与空/错/降级状态下无页面横向溢出；键盘完成筛选、任务完成与详情返回 |
| 生命周期 | UI 禁用/启用仍只访问原 Host；已有数据与后台作业保持；Web 与 Desktop 证据分别记录，文件级 HMR/真实 Session 专项不因改版自动视为通过 |

## 北极星约束

**Academic Agent 的 UI
负责让用户看清事实、调整计划和控制自动化；内核负责保存权威状态；确定性程序负责日常重复工作；Agent
只在真正需要智能时介入。**

DSH Desktop 和 Web 是入口，不是 Academic Agent
的业务核心。前端可以替换，用户的学业事实和后台自动化不应随 UI
加载、卸载或重构而丢失。
