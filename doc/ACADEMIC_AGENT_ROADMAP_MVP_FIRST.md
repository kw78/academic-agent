## 0. 使用规则：一份路线图，连续执行

这份文件不是做几个任务就重写一次的临时计划，而是从当前代码向成熟产品演进的持续执行底图。

1.  从最靠前的未完成任务开始，先处理 P0，再处理其依赖项。
2.  一个任务完成后，执行测试、更新状态并继续下一个可执行任务，不因完成一个阶段就重做总体规划。
3.  只有 Intent
    改变、架构约束被证伪、出现影响多项任务的重大阻塞，或真实使用揭示必要的新需求时，才调整总体路线。
4.  非阻断需求进入后文停车场，不打断当前垂直闭环。
5.  状态定义：`DONE`=实现与验收均有证据；`PARTIAL`=实现存在但有关键缺口；`BLOCKED`=外部条件阻塞；`TODO`=未完成；`PARKED`=暂不做。
6.  仓库文档中的测试数字是历史记录。本次审查没有重新运行测试，改代码前必须重新执行基线命令。
7.  自动化测试、真实平台验证、DSH Desktop
    手工验收和用户端到端验收是不同证据，不能互相替代。
8.  每个提交只解决一个逻辑问题，不夹带无关重构。

每个 Issue/提交说明必须包含：任务
ID、用户价值或阻断点、最小改动、测试结果、真实环境验证、未解决边界、数据/Schema
影响与回滚方式。

## 1. 北极星与永久架构约束

Academic Agent 是构建在 DSH/Cordis
上的个人学业自动化助手。它持续维护课程、作业、考试、任务、计划与提醒等可靠状态；只有在需要语义理解、未知页面探索、讲解或复杂推理时才使用
Agent。

核心用户流程：

1.  添加课程平台网址；
2.  用户在浏览器中自行完成登录与必要的 SSO/MFA；
3.  验证会话并读取授权范围内的页面证据；
4.  已支持平台用现有 Adapter，未知平台在必要时由 Agent 生成声明式候选；
5.  候选通过确定性验证、样本回放和真实预览；
6.  用户授权后启用；数据经 Adapter → Connector → Kernel → Event Store；
7.  系统持续更新任务、计划和提醒；
8.  用户通过 UI/DSH Agent 查询事实、理解题目和讨论复习；
9.  登录失效、网站改版或同步失败时，系统解释问题、保留有效数据并允许修复/回滚。

不可违反的约束：

-   DSH/Cordis 是宿主，不另造一套 Harness 或插件系统。
-   Kernel 是学业领域状态的权威入口；UI、Agent、Adapter、Scheduler
    不得绕过命令处理器写业务表/事件表。
-   Event Store 是事实源；核心事件与核心投影在同一事务中保持一致。
-   普通同步、去重、提醒、状态转换和基础规划使用确定性代码，不调用 LLM。
-   Agent 输出不是事实，不得自动获得访问权限、启用权限或代码执行权限。
-   新平台优先通过已有 Adapter/Manifest
    契约接入；只有真实需求证明表达能力不足时才扩展。
-   Cookie、Token、密码不进入普通配置、领域事件、日志、UI
    返回值或模型上下文。
-   空结果、部分结果、网络错误和认证错误不能静默清空最后一次有效数据。
-   可扩展性不意味着每个函数都要做成插件；不为假想需求增加抽象。

## 5. B 组：修复探测泄露与网页访问边界

### B-01 --- 移除原始 JSON 探测预览 `[P0 / DONE]`

当前 `probe.ts` 将 `result.body.slice(0, 2_000)` 作为 `jsonPreview`
返回，UI 也展示该值。响应可能包含姓名、学号、课程明细、令牌或内部字段。

实施：

-   默认移除原始 `jsonPreview`，改为只输出必要的 JSON 结构证据。
-   保留字段名、类型、数组形状、内容类型、状态码和分页迹象。
-   不把可能含个人信息的字段值原文返回给模型。
-   若未来确需查看字段样本，必须经过字段白名单、脱敏、长度限制和明确确认。
-   更新 `SourceProbeEvidence` 契约、Host API、Agent Tool 与 UI 展示。
-   让实现、测试和"仅返回脱敏证据"的文档一致。

测试：

-   构造含 `access_token`、`session`、姓名、学号、邮箱和课程明细的
    JSON。
-   断言探测结果、UI API 返回、Agent Tool 输出均不含敏感值。
-   保留 JSON 结构识别能力。
-   覆盖截断响应、无效 JSON 和空 JSON。

**验收：** Agent
能理解结构，但无法从默认探测输出获得未经必要性审查的原始 JSON 内容。

### B-02 --- Manifest 主机/协议/端口/路径授权 `[P0 / DONE]`

当前 Manifest 有 `allowedOrigins` 主机名范围，没有完整路径权限；Runtime
调用 `safeFetch` 时未传入底层支持的 `allowedPathPrefixes`。

实施：

-   明确允许协议、精确主机/显式子域规则、端口与路径前缀。
-   默认 HTTPS；HTTP 例外必须显式配置且不能携带 Secure Cookie。
-   初始 URL、模板 URL、分页 URL、详情
    URL、相对链接和每次重定向统一执行策略。
-   不默认将根域与所有子域视为同一授权范围。
-   路径按 URL path segment 语义校验，避免简单字符串前缀绕过。
-   Runtime 实际将 Manifest 权限传递给安全 HTTP 层。
-   候选验证、离线回放和正式运行使用一致策略。
-   为现有 Blackboard 与 USTC Manifest 配置最小必要路径。

测试：未授权主机/子域、路径、分页与重定向被拒绝；编码路径、点段、端口变化、HTTP
降级和相对 URL 不绕过策略；合法现有同步仍通过。

**验收：** Manifest 只能访问声明并获批的资源范围，而非同站点任意路径。

### B-03 --- 加强正则执行安全 `[P0 / DONE]`

-   审核当前 `regexSafetyError`
    对嵌套量词、重叠分支、长输入与灾难性回溯的覆盖。
-   评估线性时间正则引擎或可限制执行时间的隔离环境。
-   不把长度限制视为 ReDoS 的充分防护。
-   限制正则长度、输入长度与累计提取量。
-   验证与正式运行采用相同规则。
-   风险不明时拒绝候选并给出可理解的原因。

**验收：** 恶意正则不会无限占用 Host
主线程；失败为受控错误，不影响已有数据和后台任务。

### B-04 --- 收紧会话与 Cookie 复用 `[P0 / DONE]`

-   审核浏览器会话、Blackboard、探测工具和 Declarative Runtime 的 Cookie
    传递路径。
-   Cookie 必须符合 Domain、Path、Secure、Expiry 与来源授权范围。
-   跨子域、跨域 SSO 与重定向需要明确授权；不能仅因同属学校就放宽。
-   API/UI 不返回 Cookie、Token、密码或不透明秘密。
-   删除凭据、断开连接和会话过期不删除学业历史。
-   登录窗口关闭不能单独证明认证成功；必须验证受保护资源。

**验收：**
连接只能使用自己的秘密和获批范围；认证失败可恢复；删除秘密不影响已同步数据。

### B-05 --- 网页探测与 Agent 工具边界 `[DONE]`

-   所有网页内容视为不可信输入，不允许页面文字覆盖系统/开发者指令。
-   探测结果限制页面大小、链接数、标题长度、层级和总输出量。
-   探测链接只是候选证据，不是自动授权。
-   Agent 不能自行扩大网络权限、启用候选或执行任意代码。
-   统一脱敏错误文本、重定向 URL、查询参数和异常页面。
-   安全拒绝可记录原因，但不得记录秘密或完整敏感页面。

**验收：** 提示注入、恶意链接和异常响应不能改变权限边界或泄露秘密。

### C-03 --- 登录与验证 `[PARTIAL]`

-   从当前 Desktop UI 发起浏览器登录。
-   用户自行完成认证；系统不读取密码、不绕过 MFA。
-   验证秘密进入 Vault，UI 只显示域名/标签/状态。
-   覆盖登录失败、取消、过期、重新登录。
-   未验证会话的正式同步必须被拒绝。
-   确认登录后探测不会把认证信息送入 UI/Agent。

**验收：** 登录状态可解释、可恢复，不泄露秘密。

### C-04 --- Blackboard 预览与同步 `[PARTIAL]`

-   用真实授权会话执行预览。
-   核对新增、更新、未变、跳过、部分结果与 warning。
-   同步后在 UI 查看真实课程、作业和截止信息。
-   相同数据再次同步应 no-op。
-   覆盖认证失败、网络失败、单页失败与分页触顶。
-   失败时保留旧数据并正确显示 `partial`、`auth-required` 或
    `failed`，不得伪报成功。

**验收：** 用户能在 Desktop 完成"添加---登录---预览---同步---再次同步"。

### C-05 --- 真实数据与任务价值 `[PARTIAL]`

-   核对标题、来源链接和截止时间。
-   仅日期与未知截止保持原语义，不猜午夜。
-   本地任务完成状态不冒充学校提交状态。
-   新事项能生成默认任务，但不覆盖用户已修改的预计时长/完成状态。
-   任务、计划、提醒、同步记录与来源数据一致。
-   重启后同一状态仍可读取。

**验收：** 用户能直接使用 UI 中的真实数据，无需手工改数据库。

### C-06 --- 当前候选流程验收 `[PARTIAL]`

-   从未知来源卡片发起 Agent 候选生成。
-   UI 明确说明生成由 DSH Agent 对话触发，不宣称全自动。
-   Agent 只读取脱敏探测证据。
-   候选经过验证、预览、注册、用户启用和回滚。
-   验证失败的候选不能启用。
-   启用后创建/更新 declarative source；复用会话前检查同站点与授权范围。
-   正式同步仍经 Connector/Kernel/Event Store。
-   失败/重试/回滚不影响活动版本与已有学业数据。

**验收：** 至少一个声明式候选在当前 Desktop
中走完生命周期；残留手工步骤有明确说明。

## 7. D 组：MVP 学业业务闭环

### D-01 --- 课程与来源管理 `[PARTIAL]`

-   添加、查看、归档课程与来源；身份稳定，不因显示名称变化重复创建。
-   归档停止后续同步但保留历史数据；删除凭据与归档来源语义不同。
-   UI 显示来源、最后同步时间、同步健康、认证状态与 Adapter 就绪度。
-   错误状态提供可执行的下一步，而不是只有技术堆栈。

**验收：** 用户知道课程数据来自哪里、是否最新、是否需要重新登录。

### D-02 --- 标准学业事项模型 `[PARTIAL]`

-   统一课程、作业、考试、测验的外部 ID、标题、描述、URL、时间和类型。
-   区分精确时间、仅日期和未知时间。
-   来源字段与用户本地覆盖分离。
-   记录来源与 Adapter 版本以便追溯。
-   字段缺失时发出 warning，不伪造有效值。

**验收：** 各 Adapter 通过同一领域契约进入系统。

### D-03 --- 幂等同步与变更 `[PARTIAL]`

-   相同外部记录重复同步不产生重复事项。
-   截止时间/标题变化时正确更新来源字段。
-   不覆盖本地完成状态、备注和预计时长。
-   "本次没抓到"不等于"平台已删除"；只在有明确删除证据时处理删除。
-   部分同步不触发全量清理。
-   并发同步有锁/冲突处理；只对可恢复错误有限重试。
-   `sync_runs` 记录状态、时间、数量、warning、错误类别与 Adapter 版本。

**验收：** 首次同步、重复同步、更新、部分失败与重启恢复均有确定性结果。

### D-04 --- Blackboard 与考试/测验边界 `[PARTIAL]`

-   保留真实课程、作业、文件夹分页的现有验证。
-   保留考试/测验 fixture 测试，但不得称为真实考试验证。
-   当前账号若没有考试/测验项目，UI/文档继续标记"真实环境未验证"。
-   使用已验证的 USTC 教务考试 Manifest 证明系统存在真实考试同步路径。
-   不把 USTC 的考试切片误报成完整教务适配器。
-   记录 Blackboard 课程筛选、可读范围与分页限制。

**验收：** 产品有真实作业和考试数据路径；每个平台的覆盖范围透明。

### D-05 --- 本地任务状态 `[PARTIAL]`

-   同步事项幂等创建默认任务。
-   用户能完成/重开任务、修改预计时长与本地状态。
-   来源事项与学习任务清晰区分。
-   来源更新不覆盖用户进度。
-   任务可按课程、类型、状态、截止时间筛选。

**验收：** 任务是持续可管理的本地状态，不是每次同步重建的临时列表。

### D-06 --- 基础计划与可用时间 `[PARTIAL]`

-   用户设置时区、每周可用时间、临时不可用与计划粒度。
-   Planner 不默认全天可用。
-   候选计划与已确认计划区分；可确认、放弃、锁定、解锁、归档。
-   计划不与锁定时间冲突；未安排事项有原因。
-   截止变化只触发必要重规划，不覆盖用户锁定与手动控制。
-   普通规划路径的 LLM 调用保持为零。

**验收：** 用户知道接下来做什么，也理解计划为什么这样安排。

### D-07 --- 提醒与后台自动化 `[PARTIAL]`

-   72h/24h 等阈值可配置，默认值明确。
-   同一事项/阈值去重；重启后补偿扫描不重发已处理提醒。
-   用户可暂停/恢复作业并查看运行记录。
-   UI 卸载不造成重复后台资源。
-   时区、夏令时与仅日期截止有明确规则。
-   通知历史不成为学业事实源。

**验收：** 自动化可恢复、可观察、可由用户控制。

### D-08 --- 自然语言查询与讲解 `[PARTIAL]`

-   Agent 通过受控工具读取课程、作业、考试、任务、计划与提醒。
-   "最近有什么作业/哪些快截止/今天先做什么"以已保存数据为事实依据。
-   事实与推断建议明确区分；无数据/数据过期/工具失败时诚实回答。
-   用户提供题目时可获得步骤讲解；若没有课程材料，不得声称读取过材料。
-   Agent 建议不能直接变成已确认计划；写入操作受可信宿主授权。
-   无模型时同步、去重、任务状态和基础规划仍可工作。

**验收：** Agent
是已有学业状态的交互与推理层，不是另一个不可追溯的数据源。

# 第二部分：MVP 后的持续演进

## 9. F 组：Declarative Adapter 通用能力

### F-01 --- 固定 Manifest 契约 `[DONE]`

-   明确 `schemaVersion`、`adapterId`、版本、数据类型、来源与授权范围。
-   定义请求、分页、字段映射、时间处理、稳定 ID 与错误语义。
-   区分语法合法、权限合法、样本通过、真实数据可用、已批准启用。
-   缺少能力时显式报错，不静默替换实现。
-   建立版本兼容测试与迁移策略。

**验收：** Manifest 是可验证、可演进的运行契约，不只是可解析的 JSON。

### F-02 --- 字段转换与类型处理 `[DONE]`

按真实平台需求逐项增加：

-   日期/时间/时区/仅日期/未知值转换；
-   字符串清理、数字/布尔类型、常量、模板和默认值；
-   必需字段缺失处理与诊断；
-   HTML Selector 与 JSON Path 边界行为；
-   多字段组合稳定 ID 与来源 URL 规范化；
-   结构变化检测：必需字段消失时标记退化，不静默同步错误数据。

**验收：** 每个转换都有 fixture、异常样本、重复同步测试，不影响既有
Manifest。

### F-03 --- 分页与有限内容发现 `[DONE]`

-   支持下一页 URL、页码、offset 等明确规则。
-   统一限制请求数、页数、总行数、总字节、超时和总时长。
-   每次分页重新执行主机/路径/协议/端口策略。
-   截断和部分结果不能误报完整。
-   有限发现课程内容区、文件夹与详情链接；不自动爬完整网站。

**验收：** 分页完整性可判断、限制可解释、异常不会触发数据清理。

### F-04 --- 标准接口优先 `[PARTIAL]`

新平台按此顺序评估：官方 API/导出、ICS、已授权
HTTP/JSON、已登录浏览器会话、受限页面解析，最后才考虑额外执行能力。

-   评估通用 ICS Adapter。
-   评估 OAuth/API 凭据模型与当前 Vault 的适配方式。
-   为每个平台记录授权范围、速率限制、认证失效行为和真实验收数据。
-   不为每个网站建立独立 UI 或重复 Connector。

**验收：** 新来源主要通过稳定契约接入，平台差异不渗入 Kernel。

### F-05 --- 平台覆盖策略 `[PARTIAL]`

-   先完善 Blackboard 与 USTC 考试切片的可靠性。
-   新平台必须有实际用户需求与合法访问方式。
-   每个平台只声明真实验证过的数据类型。
-   选择一个有实际需求的平台，证明相同 Runtime/Connector/Kernel/UI
    可复用。
-   记录新平台需要的 Manifest、代码、测试和人工操作量。

**验收：** 平台扩展是低成本复用，不是把独立爬虫重新包装。

## 10. G 组：Agent 辅助接入与候选修复

当前候选生成仍在 DSH Agent 对话中触发，这是阶段性设计，不是 MVP
阻断项。先保证安全和验证，再逐步减少人工操作。

### G-01 --- 接入状态机 `[DONE]`

-   统一状态：未配置、待登录、已登录未验证、已验证、待探测、候选生成中、待验证、验证失败、待启用、已启用、同步中、部分同步、失败。
-   UI 只显示当前状态允许的下一步操作。
-   Host 是状态权威，客户端不能自行假定成功。
-   重复提交、取消、超时、刷新不创建重复来源/候选。
-   错误区分认证、网络、权限、解析、Schema、样本不足和数据质量。

**验收：** 用户不需要理解 Engine/Manifest
内部结构，也能知道当前状态和下一步。

### G-02 --- 结构化探测证据 `[DONE]`

-   在 B
    组安全修复后提供脱敏标题、结构、表格列、链接文本、内容类型、分页迹象与
    JSON 形状。
-   限制证据大小、链接数、页面数与执行时间。
-   用户可查看使用了哪些页面/字段证据，但默认不展示秘密或大段原文。
-   记录脱敏来源 URL、时间、状态和摘要哈希。
-   网页内容不能成为系统指令或授权依据。

**验收：** Agent
得到足够的结构信息生成候选，同时最小化数据暴露且可审查。

### G-03 --- 有限多页采样 `[PARKED]`

-   从用户明确选择的课程/作业入口开始。
-   有限识别课程列表、作业列表、详情和分页页面。
-   每扩展一个页面都校验授权范围。
-   限制页面数、请求量、并发、延迟和采样深度。
-   只保留生成 Manifest
    所需的结构化样本；原始页面只可临时本地保存并有清理规则。
-   采样失败返回"证据不足"，不让 Agent 猜测缺失字段。

**验收：** 采样有界、可审计，不演变为无界通用爬虫。

### G-04 --- 候选生成、验证和修订 `[DONE]`

-   Agent 输出 Manifest 候选与证据映射说明。
-   Validator 检查 Schema、网络权限、正则安全、必需字段、数据类型和稳定
    ID。
-   离线回放覆盖新增、更新、未变、缺失与重复。
-   真实预览展示差异和警告，不直接写正式领域状态。
-   验证失败返回结构化诊断，允许 Agent 修订候选。
-   每次修订都重新执行全套验证。
-   候选、活动版本与回滚版本始终分离。
-   记录候选版本、验证报告和批准结果，不记录秘密。

**验收：** Agent 减少编写/排错成本，确定性验证器决定候选能否运行。

### G-05 --- 审批与权限控制 `[DONE]`

-   UI 显示候选访问范围、数据类型、字段、验证报告和预览差异。
-   启用必须由用户明确执行。
-   Host API 校验注册、启用、回滚与来源修改权限。
-   模型输出中的 `confirmed`/`approved` 不能证明用户授权。
-   Agent Tool 注册/启用继续要求可信宿主逐次授权。
-   回滚后停止使用新版本，保留失败版本用于诊断。

**验收：** Agent
可以提出能力，用户拥有启用权；未验证候选不能进入正式同步。

### G-06 --- 失败修复建议 `[DONE]`

-   识别登录失效、页面结构变化、字段缺失、分页异常、超时和限流。
-   先给诊断与建议，不自动放宽网络权限。
-   对选择器/字段映射提出候选版本，并用历史样本比较旧版与候选版。
-   真实预览通过前不替换活动版本。
-   不确定时要求用户补充样本或确认。
-   回滚适配逻辑，不自动回滚/改写领域事件。

**验收：** 自动修复只改变适配逻辑，不篡改已同步的学业事实。

## 11. H 组：个性化学业助手

### H-01 --- 用户偏好与规则 `[DONE]`

-   支持课程优先级、任务重要性、预计时长、学习偏好与可用时间。
-   区分用户明确设定与 Agent 推断。
-   偏好持久化、可查看/修改/删除；Agent 不能悄悄修改用户规则。
-   默认策略保守、明确、可解释。

**验收：** 个性化状态是用户可控的持久设置，不是隐藏在聊天中的猜测。

### H-02 --- 更实用的学习计划 `[PARTIAL]`

-   按截止时间、预计时长、优先级和可用时间排序。
-   任务过多时解释冲突、风险与未安排原因。
-   用户可锁定时间块、手动调整和确认候选计划。
-   截止变化只重算受影响部分，保留锁定和手动修改。
-   只有真实案例证明现有算法不足时才引入复杂优化器。
-   用真实任务案例评估计划，而不只测函数输出。

**验收：** 计划减少整理时间，用户能理解并修正建议。

### H-03 --- 题目讲解与课程上下文 `[PARTIAL]`

-   Agent 入口可带入当前课程、作业标题和相关上下文。
-   用户可以输入题目、粘贴文本或提供授权资料。
-   区分题目原文、平台事实、推导过程与建议。
-   没有课程材料时不得声称读取过材料。
-   讲解可以按用户要求调整详细程度。
-   不自动提交作业或修改学校平台。
-   对截止/作业要求优先引用本地已保存来源。

**验收：**
用户用同一助手管理学业并请求讲解，数据与教学不成为两个互不相干的产品。

### H-04 --- 复习与跨课程分析 `[PARTIAL]`

-   按课程/考试整理复习事项。
-   根据截止、用户标注的薄弱点和可用时间给出建议。
-   允许用户反馈建议是否有用。
-   建议标注依据和不确定性。
-   没有数据时不生成虚假成绩趋势、掌握度或能力评分。

**验收：** 智能建议可追溯、可纠正，不伪装成客观测量。

### H-05 --- 资料与知识引用（按需） `[PARKED]`

-   只有真实需求出现时才增加课程资料索引。
-   文件存储与索引分离，索引可重建。
-   检索结果保留来源；区分用户资料、学校页面与外部网页信任边界。
-   明确数据保留、删除与模型发送边界。
-   不把向量数据库/知识图谱作为学业 MVP 前置条件。

**验收：** 资料检索确实提升讲解质量，且不破坏学业事实源。

## 12. I 组：可靠性、恢复与工程成熟度

### I-01 --- 事件与投影一致性 `[PARTIAL]`

-   核心事件与核心投影同事务提交。
-   覆盖命令幂等、并发冲突、重复事件和失败回滚。
-   投影重建后业务状态等价。
-   新事件 Schema 有 Upcaster 与历史样本。
-   扩展投影不成为事实源。
-   事件可追溯到来源与 Adapter 版本。

### I-02 --- 调度与插件生命周期 `[PARTIAL]`

-   Host 重启后作业恢复且不重复注册。
-   插件停用释放监听器、计时器和外部资源。
-   Planner/Tools 独立卸载不破坏 Host 与已有计划。
-   UI 卸载不造成重复后台作业。
-   分别记录 profile 级卸载、进程重启、文件级 HMR 的测试结果。
-   DSH 升级时重新验证 Remote API、Tool Registry 与 Cordis
    生命周期契约。

### I-03 --- 备份、恢复与迁移 `[DONE]`

-   数据库位置和 profile 关联可发现。
-   备份快照一致，不直接复制活跃写入中的 SQLite 文件。
-   在独立目录实际恢复并运行完整性检查。
-   验证事件位置、投影、任务、计划、作业与提醒恢复。
-   迁移前备份并记录版本；迁移失败时明确停止。
-   提供用户可理解的数据导出/删除说明，不绕过领域命令改业务表。

### I-04 --- 日志、诊断与隐私 `[DONE]`

-   统一错误码与可理解的错误说明。
-   每次同步关联 source、Adapter 版本、运行 ID、时间、状态和 warning。
-   不记录 Cookie、Token、密码、Authorization 头或带敏感查询参数的 URL。
-   诊断 HTML/探测输出限制在本地临时目录，并有保留/清理策略。
-   日志可以定位失败，但不能成为第二个无边界个人数据仓库。

### I-05 --- 性能与资源上限 `[DONE]`

-   请求、响应体、页面数、记录数、时长与重试次数有统一上限。
-   记录可重复的性能基线，不把单次本机快测当 SLA。
-   在 1k/10k 级事项与事件规模检查查询、同步、投影重建。
-   对长分页、慢站点、超大响应与并发进行故障测试。
-   只有实际瓶颈出现后才引入 Snapshot、缓存或复杂索引。

### I-06 --- 安装与升级 `[PARTIAL]`

-   明确 Node/DSH 兼容范围。
-   验证 DSH/UI 构建产物、profile 安装与重启。
-   验证升级保留数据库、凭据与用户设置。
-   升级前提示备份，升级失败提供恢复步骤。
-   Desktop 占用默认数据库时不启动第二个 Host。
-   减少手工编辑 profile JSON；若 DSH 没有受支持的安装
    API，明确记录限制，不用脆弱脚本伪装成稳定安装器。

**验收原则：**
备份必须证明可恢复；生命周期必须证明资源可释放；性能改进必须来自可重复测量。

## 13. J 组：受限脚本扩展（独立决策，非 MVP）

只有真实平台证明声明式 Manifest
无法合理表达复杂交互或转换时才启动。先确认新增字段、标准 API
或普通配置不能解决。

若启动，必须完成：

-   定义脚本输入/输出契约、版本与权限。
-   使用独立进程/强隔离环境，不在 DSH Host 主进程执行模型生成代码。
-   默认无文件系统、环境变量和任意网络访问。
-   网络经受控代理并遵循同一主机/路径/端口策略。
-   CPU、内存、执行时间、输出大小和请求数有硬限制。
-   脚本只能读取最小必要脱敏样本并输出候选标准化记录。
-   不允许访问 SQLite、Event Store、Vault、Host 服务或 DSH 内部对象。
-   每次变更需样本回放、权限检查、用户批准与版本回滚。
-   测试恶意脚本、死循环、内存耗尽、越权网络和异常输出。

**验收：** 即使脚本恶意或失败，也无法绕过 Kernel 或破坏已有数据。Cordis
disposer、普通 Worker 或 Node `vm` 不得未经威胁模型验证就称为安全沙箱。

## 14. K 组：可插拔能力与更广泛个人自动化

### K-01 --- 能力契约与注册 `[PARTIAL]`

-   只为真实需要独立启停、替换或复用的能力定义插件契约。
-   契约包含输入、输出、错误、权限、版本和生命周期。
-   缺失能力返回 `CAPABILITY_UNAVAILABLE`，不静默替换实现。
-   插件注册、启用、停用、升级有可观察状态。
-   停用扩展不破坏核心状态。

### K-02 --- 扩展配置与用户控制 `[PARTIAL]`

-   用户可查看已启用能力与授权范围。
-   支持停用、恢复、配置和撤销授权。
-   升级失败保留最后一个有效版本。
-   用户规则与插件内部状态分开存储。
-   插件卸载不能清理用户业务数据。

### K-03 --- 用学业场景证明复用 `[DONE]`

-   优先复用连接、调度、事件与 Agent 契约。
-   新领域先独立验证，不把通用助手愿景扩成大一统业务模型。
-   只有多个真实用例重复出现才抽象共用层。
-   不建设插件市场、多租户 SaaS 或分布式平台，除非有明确产品需求。

## 15. L 组：长期功能池

这些方向在路线图中占有固定位置，但不要求同时实施；每项都必须由真实需求触发。

### 数据源

-   ICS/日历订阅 Adapter。

## 17. 各阶段退出条件

### MVP 收尾

-   探测默认不把原始 JSON 值送进 Agent。
-   Manifest 访问范围在实际 HTTP 请求中生效。
-   当前 DSH Desktop 构建完成手工端到端验收。
-   至少一个真实平台的课程/作业同步在 UI 中可用。
-   有真实考试路径，或明确说明当前真实覆盖限制。
-   任务、计划、提醒与 Agent 查询使用同一持久化学业状态。
-   重复同步、部分失败、认证失效和重启不会损坏已有数据。
-   关键命令通过，文档与证据一致。

### Adapter 扩展

-   新平台优先通过 Manifest/现有 Adapter 契约接入。
-   权限、分页、字段映射与错误状态可验证。
-   候选必须验证并批准后才启用。
-   不同平台的实际用例证明 Runtime/Connector/Kernel 可复用。
-   平台差异不渗入核心领域模型。

### Agent 自扩展

-   探测证据最小化且脱敏。
-   Agent 能生成、验证和修订候选，但不能自批或扩大权限。
-   多页采样有硬上限与审计记录。
-   修复候选经历史样本和真实预览后才替换活动版本。
-   任意代码执行必须先满足第 13 节全部隔离条件。

### 长期产品

长期路线不是"所有功能都必须做完"。只有真实需求存在、验收清楚且不破坏核心不变量时才实施；无用户价值的能力可以永久留在停车场。

## 18. 全项目验收原则

-   `npm run typecheck` 通过。
-   `npm test` 通过，测试结果与当前代码/文档一致。
-   `npm run build:dsh` 与 `npm run build:ui` 通过。
-   真实环境能力有真实记录；无法验证的边界明确标记。
-   新增安全边界有恶意输入与越权用例。
-   新增领域行为有事件、投影、幂等与失败恢复测试。
-   新增 Adapter 有 fixture、重复同步、部分结果与真实来源说明。
-   UI 状态来自 Host 权威响应，不由客户端假定成功。
-   Agent 不绕过 Kernel、凭据权限或用户审批。
-   文档只记录实际完成能力，不把计划当成果。
-   失败可定位，用户数据可恢复。
-   变更范围小、可审查、可回滚。
