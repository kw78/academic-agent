## 一、项目目标

Academic Agent
不是一个简单的课程表，也不是一个可以随意执行网页脚本的万能爬虫。

项目需要形成一个可长期维护的个人学业自动化系统。用户只需提供课程平台网址、完成登录并授权，系统就应尽可能自动完成平台识别、适配器生成、数据验证、首次同步和后续维护。

最终用户流程：

1.  添加课程平台并完成授权登录。
2.  验证会话有效性，识别课程、作业和考试等数据入口。
3.  由 Agent 生成声明式 Adapter 候选。
4.  通过静态检查、样本回放和真实数据预览。
5.  用户明确授权后启用适配器。
6.  通过 Connector 和 Kernel 完成首次同步及后续增量同步。
7.  自动生成学习任务，参与计划、提醒和进度管理。
8.  网站改版、登录失效或同步异常时，能够定位问题、修复或回滚。

### 核心架构约束

-   Kernel 是学业业务状态的权威入口。
-   Event Store、核心投影与命令处理保持一致性。
-   Connector 负责同步协调和标准化，不直接写业务表。
-   普通同步、去重、提醒和基础规划不依赖 LLM。
-   Agent
    可以生成候选、分析错误和提出修复建议，但不能自行证明授权或绕过安全策略。
-   新网站优先增加
    Manifest；只有声明式规则确实无法表达时，才考虑新的执行能力。
-   任何失败、部分同步或空结果都不得破坏最后一次有效数据。

## 五、M1：抓取安全与凭据加固

**目标：在扩大 Agent
自动接入范围之前，确保受限抓取不能轻易越权访问网络或泄露秘密。**

### 1. DNS 与网络目标

-   [x] 将请求前 DNS
    检查与实际网络连接绑定，避免检查通过后因重新解析而访问其他 IP。
-   [x] 对每次初始请求、分页请求及重定向执行统一的目标地址检查。
-   [x] 明确限制协议、主机、端口和必要的路径范围。
-   [x] 默认强制 HTTPS，并对例外配置实施显式约束。
-   [x] 保留私有地址、回环地址、链路本地地址和云元数据地址的阻断规则。
-   [x] 验证重定向不能绕过原有授权范围。

### 2. Manifest 执行限制

-   [x] 对正则表达式设置安全约束，防止灾难性回溯阻塞进程。
-   [x] 限制单次响应大小、分页数量、请求次数、执行时间和累计采集量。
-   [x] 明确哪些字段允许拼接为请求 URL，防止模板变量引入意外目标。
-   [x] 对相对 URL、查询参数和分页链接统一执行访问策略。
-   [x] 验证网页正文中的提示注入不能改变 Agent 权限。

### 3. 凭据保护

-   [x] 将 Source Config 改为严格的 Engine 专属
    Schema，而非仅依赖敏感键名黑名单。
-   [x] 检查 `sessionCookie`、`clientSecret` 等变体和包含认证参数的
    URL。
-   [x] 保证 Cookie、Token、密码和凭据引用不会进入普通日志、事件、UI
    响应及模型上下文。
-   [x] 验证断开连接、删除凭据和会话过期不会意外删除已有学业数据。
-   [x] 为上述边界补齐自动化回归测试。

### 验收条件

所有安全策略均有针对性测试。恶意 URL、越权重定向、DNS
解析变化、异常正则和敏感配置必须得到明确拒绝或受控失败，而不是依赖开发者约定。

在这一阶段完成之前，不启用任意脚本执行，也不扩大 Agent 的网络权限。

### M3 核对记录（2026-10-28）

-   “连接”页新增“快速添加平台”：填写 HTTPS 网址与类型后生成非敏感配置，

-   同步：`sync_runs` 记录状态、错误码、警告与计数；同源并发锁、5xx/429/超时有限重试、认证失败不重试均有测试。
-   性能（本机 Node v22.23.2，内存 SQLite，1000 事项）：首次同步 225 ms，重复 no-op 220 ms，查询 1 ms，重建投影 39 ms；数值记录在 `docs/operations.md`，不是发布 SLA。
-   候选回滚：启用 v1.1.0 后回滚到 v1.0.0，`adapter-<id>` 数据源配置回到旧版本；学术事项与领域事件数量不变。
-   诊断保留：默认不自动轮转；探测/调试 7 天、备份 30 天、事件长期保留；清理命令与数据删除步骤写入 `docs/operations.md`。
-   用户文档：安装/启用插件、登录授权、同步失败、备份恢复、故障排查、数据删除与已知限制已覆盖。
-   仍未完成：真实 DSH Session 生命周期与文件级 HMR 需要在实际 DSH/桌面进程中手工验收；此前已验证 profile 级插件禁用/启用与后台作业继续运行，但本轮未重复执行。

### 验收条件

系统可以从数据库备份恢复；同步和调度可以在重启后继续运行；凭据失效、网络故障和解析失败不会造成数据丢失；插件卸载与重载不会产生重复任务或后台资源。

## 十一、当前不做的事情

为了控制风险和避免过度设计，以下事项不列入近期必需交付：

-   不承诺任何网站都能自动接入。
-   不在 DSH Host 主进程执行未经审查的 AI 生成代码。
-   不为了自动化而绕过验证码、MFA、访问控制或平台授权限制。
-   不在首个平台核心闭环尚未完成时，同时铺开大量平台。
-   不为了引入 AI 而把确定性同步、提醒和规划改造成 LLM 驱动。
-   不重写已经稳定的 Kernel、Event Store 和核心领域模型。
-   不将附件下载、成绩抓取和远程提交作业混为一项工作；这些能力必须单独评估权限与风险。

如果未来确实需要 JavaScript
适配器，必须先设计独立执行环境、网络权限、文件访问隔离、执行时间限制和可撤销授权。Cordis
插件生命周期隔离不等于安全沙箱。

## 十三、统一完成标准

每个里程碑完成前，必须同时满足：

-   `npm run typecheck` 通过。
-   `npm test` 通过，测试结果与文档一致。
-   新增安全边界、业务不变量和失败恢复行为均有自动化测试。
-   未经授权的候选、写入和网络访问均被拒绝。
-   凭据、Cookie 和 Token 不进入日志、事件或普通 Agent 上下文。
-   同步结果能够追溯到数据源、适配器版本和同步运行记录。
-   文档同步更新，未完成的事项明确保留。
-   代码变更小步提交，失败时可以恢复到最后一个有效版本。

## 十四、最终验收目标

Academic Agent
的下一阶段成功，不以新增多少模块、支持多少网站或生成多少行代码衡量。

真正的验收标准是：

**用户提供一个有权访问的课程平台网址，完成登录并授权后，系统可以自动完成探测、适配器生成、确定性验证、数据预览和首次同步；随后稳定地维护课程、作业、考试和学习任务。遇到网站改版、会话过期或解析错误时，系统能够说明原因、保留有效数据、修复或回滚。**

这条完整流程通过真实环境验收后，再扩大平台覆盖范围和自动化程度。

安全与正确性优先于自动化程度；可验证的真实闭环优先于抽象能力的数量；稳定的确定性内核优先于不断扩大的
Agent 权限。
