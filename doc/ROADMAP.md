## 1. 目标与范围

本路线图的目标不是一次性实现"适配所有网站的万能爬虫"，而是按风险递增的顺序，交付一个可验证、可恢复、可扩展的学业数据接入系统。

最终用户应能够：

1.  添加一个受支持的课程平台。
2.  在隔离的浏览器中自行完成登录，不向 Agent 提供明文密码。
3.  验证登录会话确实能访问受保护的课程页面。
4.  识别或配置平台的数据提取方式，并预览即将导入的课程、作业和考试数据。
5.  在明确授权后执行首次同步，随后手动或定时同步。
6.  查看同步状态、数据来源、失败原因，并在平台改版或会话过期后恢复。
7.  在需要时由 AI
    辅助生成新的适配器候选版本，但未经校验和授权不得自动启用。

### 非目标

-   不承诺未经适配即可兼容任意网站。
-   不绕过 CAPTCHA、MFA、访问控制、付费墙或平台授权限制。
-   不允许模型生成的任意代码未经隔离测试就进入 Host 主进程。
-   不让 Connector 或 UI 绕过 Kernel 直接修改业务数据库。
-   不以"Cookie 已保存"作为"平台已连接、数据可同步"的证明。

## 4. M0 --- 安全与回归基线

### 工作项

-   [x] 建立并记录当前分支的测试、类型检查、构建和 lint 命令及结果。
-   [x] 修复 Cookie 请求头生成逻辑：依据目标 URL 对 Cookie 的
    domain、path、secure、expiry 等属性进行筛选。
-   [x]
    限制会话请求只能访问明确授权的域名/主机；重定向的每一跳都重新校验。
-   [x] 对回环地址、私有地址、链路本地地址、云元数据地址等实施 SSRF
    防护，并考虑 DNS 重绑定。
-   [x] 默认禁止 HTTPS 会话降级到 HTTP。
-   [x]
    对请求设置超时、重定向次数上限和响应体的真实字节上限；使用流式读取，而不是下载完整响应后才截断。
-   [x] 对登录 URL、查询参数、Cookie、Token 和错误消息进行日志与 UI
    脱敏。
-   [x] 明确网页正文是"不可信外部数据"，不能被当成系统指令。
-   [x] 为上述行为补充单元测试和集成测试。

> 2026-10-28 落地说明：M0 已实现并通过 117 项测试。DNS 在每次请求/重定向前解析并校验地址，但尚未用自定义 dispatcher 固定解析结果，DNS rebinding 作为残余风险记录在 `docs/testing.md`。

### 验收标准

-   不适用于目标 URL 的 Cookie 不会被发送。
-   任何重定向都必须通过目标地址策略；不允许通过跳转绕过限制。
-   受限地址、非 HTTP(S)
    URL、超大响应、超时和异常重定向均有明确失败结果。
-   日志、UI 和普通 Agent 工具结果不暴露 Cookie 或认证 Token。
-   安全测试可重复运行，失败时能定位到具体规则。

-   [ ] 表单根据所选 engine

### 验收标准

-   不填写可选 ID 也能成功创建并返回真实数据源。
-   表单不能创建引擎、认证方式和登录模式明显冲突的配置。
-   用户能明确区分"已保存""待验证""可同步"和"同步失败"。
-   API
    返回错误时，不会静默留下用户无法识别的半成品对象；若操作已持久化，返回结果必须如实反映。

## 6. M2 --- 一个真实平台的只读垂直切片

先选择一个已获授权、便于测试的课程平台。不要同时铺开多个平台。具体平台应由项目维护者根据可用测试账号、平台条款和实际课程数据确定。

### 工作项

-   [ ]
    记录平台登录方式、受保护页面、课程列表入口、作业列表入口和分页行为。
-   [ ] 让用户在隔离浏览器完成登录。
-   [ ] 验证会话能读取至少一个受保护的课程页面。
-   [ ] 实现最小只读
    Adapter：读取课程和作业/考试信息，不执行平台写操作。
-   [ ] 将原始页面转换为统一的标准化课程与学业事项结构。
-   [ ] 为来源记录稳定的外部 ID；没有外部 ID 时设计可重复的确定性指纹。
-   [ ] 将 Adapter 输出交给既有 Connector/Kernel
    写入路径；不得直接改业务表。
-   [ ] 实现同步预览、首次导入确认、同步运行记录、失败状态和重试。
-   [ ] 用脱敏的真实页面样本或合成 HTML/JSON 建立回归测试夹具。
-   [ ] 对平台条款、数据最小化、保留期限和账号授权进行检查。

### 验收标准

-   测试账号可完成"登录 → 验证 → 预览 → 用户确认 → 同步 → UI
    展示"的端到端流程。
-   同一数据重复同步不会不断产生重复事项。
-   单个项目/事项字段缺失时能报告部分失败或跳过原因，而不是静默伪造字段。
-   登录过期、权限不足、网络超时和平台结构变化能被区分。
-   首个平台没有完成之前，不以"通用爬虫已完成"对外描述进度。

## 7. M3 --- 声明式 Adapter Runtime

先用声明式配置覆盖常见的 HTML/JSON 提取，不要一开始就生成任意
JavaScript。

### 候选能力

-   [ ] 定义有版本的 Adapter Manifest。
-   [ ] 支持允许的请求入口、页面类型、CSS/XPath 或 JSON
    路径映射、分页规则和字段转换。
-   [ ] 为课程、作业、考试等目标定义严格的输出 Schema。
-   [ ] 对域名、请求方法、路径范围、响应类型和页面数量设置权限。
-   [ ] 为 Manifest 提供静态验证、样本回放和版本比较。
-   [ ] 对时间、时区、截止时间、缺失值和 HTML 文本清洗建立统一规则。
-   [ ] 维护已知页面样本，测试平台页面变化是否破坏解析结果。

### 验收标准

-   无法通过 Schema 验证的配置不能启用。
-   适配器只能请求授权范围内的页面。
-   相同输入和同一版本产生可预测的标准化结果。
-   适配器版本可回滚，正式同步使用的版本可追溯。
-   声明式表达无法满足某平台需求时，必须说明原因，再决定是否进入代码沙箱阶段。

## 8. M4 --- AI 辅助适配器生成

AI 只生成候选版本，不直接部署。候选适配器需要经过确定性的验证流程。

### 推荐流程

1.  **采集证据：** Agent
    通过已授权会话读取有限的页面样本和必要的结构信息。
2.  **生成候选：** 优先生成声明式 Manifest；只有必要时才生成脚本。
3.  **静态检查：** 验证 Schema、权限范围、危险 API、依赖与版本信息。
4.  **隔离运行：**
    在独立沙箱内运行候选，不授予任意文件、网络或主进程权限。
5.  **样本测试：** 用固定样本和合成边界样本验证解析结果。
6.  **结果预览：**
    展示将新增、更新、跳过的课程和事项，并突出低置信度字段。
7.  **用户授权：** 用户确认后，才把候选版本注册为可用版本。
8.  **灰度与回滚：**
    首次启用限制数据范围；错误率或解析质量异常时停止并回滚。
9.  **持续维护：** 记录生成模型/提示版本、证据摘要、测试结果和人工修改。

### 验收标准

-   未授权候选不能被正式同步调度器调用。
-   候选代码不能直接访问主进程凭据库、任意文件或未授权网络。
-   每个已启用版本都有来源、权限、测试结果、审批记录和回滚目标。
-   页面内容中的恶意指令不会改变 Agent 的系统规则或扩大候选权限。
-   生成失败时保留最后一个有效版本，不以未经验证的候选覆盖它。

## 10. 横向质量门槛

每个阶段都应遵守以下要求：

### 正确性

-   标准化输出必须经过 Schema 校验。
-   同步操作必须可重复执行，且重复输入不产生重复事项。
-   原始数据、标准化结果和最终写入结果之间应可追溯。

### 安全性

-   凭据不进入普通配置、日志或模型上下文。
-   外部网页内容始终视为不可信数据。
-   AI 生成的代码不在 Host 主进程内直接执行。
-   用户授权、数据源权限和网络权限均采用最小权限原则。

### 可恢复性

-   同步失败不应破坏最后一次有效数据。
-   解析器更新必须有版本和回滚路径。
-   会话失效应要求重新认证，不应无限重试或伪报成功。

### 可测试性

-   单元测试覆盖解析、Schema 和状态转换。
-   集成测试覆盖凭据隔离、会话抓取和同步路径。
-   端到端测试至少覆盖一个真实平台的只读流程。
-   每个安全修复都应有针对性的回归测试。

## 11. 建议的首批 Issue

建议按以下顺序建立小而可验收的 Issue：

1.  `security: enforce cookie scope and secure attributes`
2.  `security: validate every redirect and block unsafe network targets`
3.  `security: enforce streaming response byte limits and request timeouts`
4.  `fix: return generated sourceId from createSource`
5.  `fix(ui): derive auth and login mode from selected engine capabilities`
6.  `feat(ui): separate session saved, session verified, adapter ready and sync health`
7.  `test: add session SSRF, redirect, cookie and body-limit regression suite`
8.  `feat(connector): complete one authorized read-only LMS vertical slice`
9.  `feat(adapter): define versioned declarative adapter manifest`
10. `feat(agent): generate and validate adapter candidates in an isolated sandbox`

## 12. 路线图决策原则

遇到进度冲突时，按以下顺序取舍：

1.  凭据安全与用户数据正确性。
2.  一个真实平台的完整可验证闭环。
3.  可诊断、可恢复的同步能力。
4.  可复用的声明式适配器。
5.  AI 自动生成与更广泛的平台覆盖。

**阶段性成功的标准不是代码模块越来越多，而是用户能安全地连接一个平台、可靠地得到正确数据，并在失败时知道原因、能够恢复。**
