# 0019 — 多步骤操作的失败恢复语义

- 状态：已接受
- 日期：2026-10-28

## 背景

删除课程会逐项归档事项与任务；候选启用会先切换激活版本，再创建或更新同步源。两处都把 `CONFLICT` 当作可跳过或忽略的状态，可能留下“课程已删但事项仍活动”或“激活版本没有对应同步源”的半完成状态。

## 决定

1. **同库多步骤操作**（课程删除）：
   - 每一步仍通过领域命令与 `expectedVersion` 校验。
   - 遇到 `CONFLICT` 时重读当前版本并重试，最多 3 次；若重新读取发现对象已归档/已删除，视为该步已完成。
   - 任一步最终失败则返回 `CONFLICT`，**不执行课程删除**；已归档部分保留，用户可重试删除补齐。不得把冲突当作成功。
2. **涉及外部步骤的操作**（候选启用）：
   - 先记录原激活版本，再切换激活版本。
   - 同步源创建/更新失败时，尝试回滚到原激活版本，并返回包含失败原因的错误；没有旧版本时明确说明需要重试启用。
   - 会话复制失败仍是警告，不撤销激活。
3. 事务边界不扩张：不引入跨 registry 与数据库的分布式事务，也不把多步操作伪装成原子操作。

## 后果

- 失败结果可解释、可重试，不留下“看起来成功”的错误状态。
- 课程删除可能留下“事项已归档、课程仍在”的中间态，但返回值明确且重试即可完成。
- 候选启用失败后活动版本与同步源保持一致；仍需在 UI 中显示真实中间态。
