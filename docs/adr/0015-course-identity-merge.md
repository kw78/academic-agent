# 0015 — 同学期同名课程合并

- 状态：已接受
- 日期：2026-10-28
- 相关：ADR 0014、Connector 课程注册、Query/Projection、课程维护

## 背景

同一门课可能从 Blackboard、教务系统或手工添加进入本地库，外部课程 ID 不同，标题却相同。旧逻辑只按 `(source_id, external_course_id)` 判断，导致同一学期出现两条同名课程；事项、资料和优先级也被拆到两边。

## 决策

1. **课程身份按学期 + 规范化标题**
   - 使用 `normalizeCourseTitle`（NFKC、压缩空白、小写）比较标题；键为 `(termId, normalizedTitle)`。
   - 同一学期内同名课程视为同一门课；不同学期同名课程仍分开。
2. **来源身份用别名表维护**
   - 新增 `course_source_aliases (source_id, external_course_id) -> course_id`。
   - Connector 注册课程时先查别名，再查同学期同名课程；命中则复用并记录别名，不创建新课程。
   - 手工 `addCourse` 同样复用同学期同名课程，不再产生第二条。
3. **历史重复通过显式合并修复**
   - `mergeDuplicateCourses` 按组选择最早创建的课程作为保留课程。
   - 每个事项通过新的 `AcademicItemReassignCourse` 命令写入 `AcademicItemCourseChanged` 事件，投影随之更新，保留进度/来源/事件历史；同步路径仍禁止把事项改到别的课程。
   - 资料与自动导入订阅迁到保留课程；同 sha256 的资料只保留一条。
   - 课程优先级合并到保留课程并移除重复键。
   - 重复课程用现有 `CourseDeleted` 关闭，重复来源写入别名表；之后同步同一来源会继续落到保留课程。
4. **可撤销**
   - 合并前应备份数据库；关闭的重复课程仍保留在事件历史中，投影重建不会复活重复行。
   - 资料索引中的课程 ID 是运营数据，合并时直接迁移；文件仍按 sha256 共享。

## 后果

- 新同步、手工添加、旧数据合并都不会再出现同学期同名课程。
- 合并会追加事项事件和课程删除事件，不会改写历史事件。
- 同一学期确实存在两门同名但不同的课程时会被合并；这是用户明确要求的行为，可通过重新添加不同标题的课程区分。
- 合并命令是维护操作，不在后台自动运行；CLI `course merge-duplicates` 与设置页“合并同学期同名课程”按钮可触发。

## 验证

- `tests/integration/course-merge.test.ts`：手工添加去重、同步注册去重、历史重复合并（事项/资料/订阅/优先级/别名）、事项显式改课程。
- 默认库演练（2026-10-28）：13 组重复课程合并、24 个事项迁移；合并后 `(term, title)` 无重复，备份位于 `.data/pre-course-merge-*.db`。
