# 0001 — SQLite Event Store + 同事务核心投影

- 状态：已接受
- 日期：2026-10-27
- 相关：Architecture Spec §3、§7、§8；Intent I-03、I-06

## 背景

MVP 是单用户、本地、单进程。需要可追溯的学业事实、可重建的当前状态，以及“命令提交后立即读到正确状态”的一致性。引入独立事件总线或分布式存储会显著增加部署与运维成本。

## 决策

- 采用每聚合事件流 + 全局顺序；聚合写入使用 `expectedVersion` 乐观并发。
- 事件存储、命令收据、核心投影放入同一 SQLite 数据库。
- 一次成功命令在单个事务中完成：收据检查 → 回放聚合 → 校验不变量 → 追加事件 → 更新核心投影 → 写收据 → 提交。
- 扩展消费者使用 `global_position` 持久游标异步追赶，不进入核心写事务。
- 使用数据库唯一约束、事务与流版本检查保证幂等与并发正确性。

## 结果

- 写入后可立即查询到新状态；投影失败与事件追加一起回滚。
- 核心投影可以从事件全量重建，读模型不是第二份权威事实。
- 单文件备份（`VACUUM INTO`）即可覆盖事件与核心状态。
- 未来迁移到 PostgreSQL/专用 Event Store 时，保持 Command/Event/Query 语义不变。

## 代价

- 需要维护事件 Schema 版本与 Upcaster。
- 单写者 SQLite 限制吞吐；MVP 规模可接受，扩展前需基准测试。
- `node:sqlite` 目前为实验性 API，运行时可能出现 ExperimentalWarning。
