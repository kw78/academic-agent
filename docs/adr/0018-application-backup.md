# 0018 — 完整应用备份包

- 状态：已接受
- 日期：2026-10-28

## 背景

`VACUUM INTO` 保证了数据库快照一致，但课程资料原文件位于数据库同目录的 `materials/`。只备份数据库会保留资料元数据、分块与索引，却丢失原文件；在全新目录恢复后，检索结果无法定位或重建。

## 决定

1. 保留 `backup` / `restore` 作为单库操作。
2. 新增 `backup-app`：目标是一个新目录，包含
   - `academic.db`（一致性快照）
   - `materials/` 下的原文件
   - `manifest.json`：`formatVersion`、创建时间、数据库与每个资料文件的相对路径、SHA-256、字节数
3. 新增 `restore-app`：先校验清单格式、路径安全与全部哈希，再复制到新目录；任一文件缺失或被改动即失败，并清理已创建的半成品目录。恢复后打开数据库执行 `integrity_check` 与投影一致性检查。
4. 清单路径必须是相对路径，资料条目必须位于 `materials/` 下，防止路径穿越。
5. 凭据不进入备份包；恢复后连接需要重新登录。

## 后果

- 整库迁移只需一个目录，资料原文件与索引一致。
- 备份包体积随资料增长；当前同步复制，大资料库可能耗时，后续可改为流式哈希。
- 单库备份继续可用，但文档明确提示它不含资料原文件。
