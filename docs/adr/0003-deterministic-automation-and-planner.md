# 0003 — 同步、去重、提醒与基础规划零 LLM

- 状态：已接受
- 日期：2026-10-27
- 相关：Intent I-01、I-02、I-08；Architecture Spec §11–§14

## 背景

重复查询、同步、去重、排序、截止提醒和基础排程有明确规则，不需要语义理解。把这些路径交给模型会带来成本、延迟与不可解释性，也违背“自动化优先”。

## 决策

- Connector 的 Fetch → Parse/Normalize → Reconcile 全部为确定性代码；内容 hash 与外部 ID 用于去重。
- 核心内核只根据字段差异产生事件；无变化即 no-op，同步结果写入 `sync_runs`。
- 通知 Reaction 与重规划触发都是普通事件消费者，不调用模型。
- Planner 使用确定性启发式：过滤完成项 → 按截止/优先级排序 → 扣除固定与锁定时间 → 顺序填充 → 报告不足与冲突。
- Agent 只通过 `academic_*` 工具读取事实或提交受控命令；模型的建议不会自动成为权威数据。

## 结果

- 常规同步与规划可测试、可解释、无模型费用。
- `ModelUsageMeter` 在端到端测试中保持 0 次调用（T15）。
- 需要语义推理的场景（讲解、模糊目标、未知平台）仍可由 Agent Bridge 处理，但不进入后台自动化主路径。
